# PocketLink 性能基线 · 2026-11-08

本机实测：荣耀 ELZ-AN20，Android 14，USB 有线连接，Windows 暴露 12 个逻辑处理器。完整成功采样时间为北京时间 09:50:30—09:54:58，约 4 分半。

每项先预热 5 秒，再采样约 30 秒，每 2 秒记录一次进程 CPU 时间和工作集。调用现有 ResourceSession、Relay、MicrophoneBridge、CameraBridge，未改动生产传输实现。摄像头按现有配置输入 1280×720，目标 30 fps，JPEG 转换目标 20 fps；本轮没有测量实际输出帧率。

| 状态 | 整机 CPU 平均占比 | 进程工作集合计 |
| --- | ---: | ---: |
| 待机 | 0.07% | 92.9 MB |
| 仅扬声器 | 0.06% | 111.3 MB |
| 仅麦克风 | 0.18% | 112.8 MB |
| 仅前置摄像头 | 3.72% | 798.1 MB |
| 仅后置摄像头 | 3.13% | 804.1 MB |
| 三项同时开启（前置） | 3.76% | 825.7 MB |
| 全部停止后待机 | 0.06% | 107.0 MB |

CPU 用所有纳入进程的 CPU 时间增量除以实际采样时长和 12 个逻辑处理器，100% 表示整台电脑 CPU 满载。短时样本受调度、画面内容和环境噪声影响，不应把 0.06% 和 0.07% 的差异解释为性能改善。

统计包含待机的 PocketLink、独立测试执行器、项目 ADB、FFmpeg（含启动 shim）、OBS 及 OBS 浏览器子进程。测试期间没有发现其他同名音视频工具进程。执行器和正式界面分进程运行，正式产品通常将这些后台线程放在主进程，因此这些数字用于相同测试条件下比较，不能直接作为正式产品的精确内存数值。工作集合计会重复计算共享页，也包括约 30—40 MB 的执行器开销，不是独占物理内存；没有测 GPU、功耗或手机端占用。

前置摄像头阶段，FFmpeg 工作集合计约 118.6 MB，OBS 主进程约 308.4 MB，OBS 浏览器子进程约 252.9 MB。对应 30 秒内 CPU 时间增量分别约 5.36、2.41、4.55 秒；执行器约 0.64 秒。主要优化空间在视频链路及其外部组件，单纯修改界面代码或 JPEG 分帧循环，不能消除这些组件的开销。

启动与释放：

- 扬声器首次启动约 548 ms，单独停止约 89 ms。
- 麦克风首次启动约 1159 ms，单独停止约 196 ms。
- 前置摄像头首次启动约 3984 ms；后置约 2542 ms；三项测试中的前置约 2365 ms。
- 摄像头停止约 3077—3109 ms；三项同时停止约 3293 ms。现有 OBS 退出流程最多等待 3000 ms，是下一轮应检查的地方。
- 日志确认前置使用 camera '1'、后置使用 camera '0'，均取得视频帧并启动 OBS Virtual Camera。
- 每个采样阶段均保持连接；全部停止后，未留下 FFmpeg、OBS、OBS 浏览器子进程或手机媒体采集的 ADB shell，仅保留 PocketLink、ADB 服务和设备订阅。
- 停止后占用回落。一次测试中额外保留的约 14 MB 工作集不能证明内存泄漏，需要重复周期或长期趋势验证。

本轮没有让用户拔插手机，也没有验收网易云的实际听感、腾讯会议输入、声学回声、实际输出帧率或端到端延迟。后端持续连接与虚拟摄像头启动成功不等同于这些验收通过。

建议下一轮先整理连接和资源生命周期，并优先尝试让摄像头切换复用 OBS 与输出服务，减少重复启动和停止等待；进一步对比减少 JPEG/浏览器中转的方案。音频链路目前没有显示出明显 CPU 瓶颈。

复测命令：

```powershell
./Measure-Performance.ps1
./Measure-Performance.ps1 -SummarizeOnly
```

会先停止正在使用的资源，再留下待机控制台，依次测试各项功能；正常结束后全部采集关闭。不要同时运行其他 ADB、FFmpeg 或 OBS 工作负载，因为当前诊断按进程名聚合。

原始逐进程样本位于 `.runtime/performance-samples.csv`，状态与启动日志位于 `.runtime/performance-run.log`，汇总位于 `.runtime/performance-summary.csv`。这些运行数据不提交 Git。脚本不保存音频或视频文件。早期脚本曾因测试执行器的事件对象释放顺序中断，已修正；本表只使用完整成功重跑的数据。
